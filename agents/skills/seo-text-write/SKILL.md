# Workflow: SEO-статья для блога по кластеру запросов

## Назначение

Этот workflow используется, когда нужно написать SEO-статью для раздела `Блог` на сайте Генезис по готовому кластеру поисковых запросов.

Задача статьи: закрыть интент пользователя, получить органический трафик, усилить экспертность бренда и мягко привести читателя к продуктам, услугам, кейсам или консультации Генезис.

## Обязательные входные данные

- Тема статьи.
- Главный запрос кластера.
- Список поддерживающих запросов.
- Интент кластера: информационный, коммерческий, сравнительный, прикладной.
- Целевая аудитория: владелец бизнеса, маркетолог, руководитель отдела продаж, операционный директор, специалист.
- Целевое действие: перейти в услугу, прочитать кейс, оставить заявку, скачать материал, запросить консультацию.

## Документы, которые нужно соблюдать

Перед написанием статьи использовать и сверяться с этими файлами:

- `D:\Генезис\Marketing\gnzsmarketing\Сайт\GPT - оптимизация.md`
- `D:\Генезис\Marketing\gnzsmarketing\Сайт\Алгоритм производства SEO статей.md`
- `D:\Генезис\Marketing\gnzsmarketing\Сайт\Гайд для увеличения вовлеченности на сайте.md`
- `D:\Генезис\Marketing\gnzsmarketing\Сайт\Чек-лист по оценке конвертера.md`
- `D:\Генезис\Marketing\gnzsmarketing\Сайт\Чек-лист публикации SEO-контента.md`

Если требования документов конфликтуют, приоритет такой:

1. Смысловая точность и польза для читателя.
2. Соответствие интенту поискового кластера.
3. Конверсия и внутренняя перелинковка.
4. SEO-структура и техническая публикация.
5. Стилистическая полировка.

## Порядок работы

### 1. Разобрать кластер

Определить:

- главный запрос;
- 5-10 самых важных поддерживающих запросов;
- вопросы пользователя;
- стадию воронки;
- что читатель уже знает;
- какое решение он хочет получить после статьи.

Не писать статью просто вокруг ключевых слов. Сначала понять задачу пользователя, потом встроить запросы естественно.

### 2. Сформулировать SEO-замысел

Перед текстом зафиксировать:

- рабочий title;
- H1;
- meta description;
- основной угол раскрытия;
- обещание статьи;
- целевое действие;
- внутренние страницы, на которые нужно дать ссылки.

Хорошая статья должна отвечать на один главный вопрос лучше конкурентов, а не быть набором общих абзацев.

### 3. Собрать структуру

Рекомендуемая структура:

- H1 с главным запросом или его естественной формой.
- Вступление: проблема, контекст, обещание пользы.
- Короткий ответ или summary в начале.
- H2/H3 под основные интенты и подзапросы.
- Практические блоки: примеры, чек-листы, ошибки, сценарии.
- Блок связи с продуктами или услугами Генезис.
- FAQ по дополнительным запросам.
- Заключение с понятным next step.

Структура должна быть удобной для чтения: короткие абзацы, списки, таблицы, логичные подзаголовки.

### 4. Написать статью

Требования к тексту:

- писать простым деловым языком;
- избегать воды, канцелярита и SEO-переспама;
- объяснять термины без снисходительности;
- давать конкретику: этапы, критерии, примеры, ошибки, признаки, чек-листы;
- показывать экспертизу Генезис через опыт внедрения, автоматизации, CRM, аналитики, маркетинга и лидогенерации;
- не обещать невозможного;
- не превращать статью в прямую рекламу.

Ключевые запросы использовать естественно:

- главный запрос — в H1 или первом экране, в одном H2, в тексте;
- поддерживающие — в H2/H3, FAQ, списках, таблицах;
- похожие формулировки — распределить по статье без повторов.

### 5. Добавить элементы вовлеченности

Свериться с `Гайд для увеличения вовлеченности на сайте.md`.

По возможности добавить:

- интерактивное или кликабельное оглавление;
- блок `Читайте также`;
- мини-чек-лист;
- таблицу сравнения;
- пример расчета;
- блок с частыми ошибками;
- CTA внутри статьи, а не только в конце;
- ссылки на релевантные кейсы, услуги, виджеты, интеграции или материалы. Релевантные продукты искать в файле `D:\Генезис\Marketing\gnzsmarketing\Продукты Генезис\Виджеты и интеграции amoCRM.md`, а услуги - в файле `D:\Генезис\Marketing\gnzsmarketing\Продукты Генезис\Продуктовая карта Генезис.md`.

### 6. Проверить конверсионность

Свериться с `Чек-лист по оценке конвертера.md`.

Проверить:

- понятно ли, для кого статья;
- есть ли следующий шаг;
- не спрятан ли CTA;
- есть ли доверие: опыт, факты, кейсы, понятные формулировки;
- снимает ли статья основные возражения;
- ведет ли текст к релевантной услуге или продукту.

### 7. Проверить GPT-оптимизацию

Свериться с `GPT - оптимизация.md`.

Текст должен быть понятен не только поисковикам, но и AI-системам:

- давать прямые определения;
- иметь ясные списки и таблицы;
- содержать короткие ответы на вопросы;
- объяснять связи между понятиями;
- использовать однозначные формулировки;
- не прятать смысл в длинных абзацах.

### 8. Финальная SEO-проверка

Свериться с `Чек-лист публикации SEO-контента.md`.

Проверить:

- Title и description;
- один H1;
- логичную иерархию H2/H3;
- наличие главного запроса и поддерживающих запросов;
- отсутствие переспама;
- внутренние ссылки;
- alt-тексты для изображений, если они есть;
- FAQ-блок, если он уместен;
- читабельность на мобильном;
- отсутствие фактических ошибок;
- готовность к публикации.

## Формат результата

Итоговый файл статьи должен содержать:

```text
# H1

Title:
Description:
URL slug:
Главный запрос:
Кластер:
Целевое действие:

## Вступление

## Основные разделы статьи

## FAQ

## Заключение и CTA
```

Если статья готовится как черновик для редактора, в начале добавить короткий блок:

- цель статьи;
- аудитория;
- интент;
- куда вести пользователя;
- какие внутренние ссылки добавить.

## Критерии готовности

Статья готова, если:

- закрывает главный интент кластера;
- может ранжироваться по основному и поддерживающим запросам;
- полезна без знания контекста компании;
- естественно связывает тему с экспертизой Генезис;
- содержит понятный следующий шаг для читателя;
- прошла проверку по обязательным документам из этого workflow.
