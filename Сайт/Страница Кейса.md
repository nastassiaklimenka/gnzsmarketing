Общие правила создания страницы кейса

- Новый кейс создаем копированием шаблона

- Все иконки в векторе (формат svg)

- Все изображения в формате jpg (кроме тех, которые с прозрачным фоном - png)

- Все изображения оптимального размера и минимизированы через сервис https://imagecompressor.com/ru/

- Если изображение плохого качества - можно улучшить через сервис https://airbrush.com/ru/image-enhancer или другой аналогичный ИИ

- Картинки не должны весить больше 100 кб (за исключением, кода это сказывается на качестве и читабельности скринов)

- На скриншотах нет персональных данных клиентов (ФИО, Телефон, конфиденциальная информация и т.д.)

- Не забыть на сайдбар алиас повесить класс CSS такой же, как в оригинальном блоке сайдбар

- В заголовках страницы, тексте и метатегах присутствуют ключевые слова по SEO

- Формула Title страницы: {SEO ключевое слово по услуге} для {ниша}: {коротко результат} 
Пример: CRM для системы электронных платежей: Рост конверсии в продажу +60%
Пример: Автоматизация бизнес-процессов в строительстве: Увеличение выручки на 80%
Пример: CRM для управления в мебельной компании: +30% к прибыли в несезон

- Description страницы: Кейс внедрения amoCRM + {краткое описание что сделано с ключевыми словами}

- Внутренняя навигация по странице работает корректно (Задача, Решение, Результат, Отзыв)

- Если есть фото клиента в отзыве - убеждаемся, что оно взято из официального сайта (и есть ссылка на сайт), из публичного источника или с разрешения владельца

- Если клиент не одобрил по какой-то причине кейс - все данные пишем под NDA

- Если сайдбар не работает: проверить есть ли на alis блоке класс CSS такой же, как в оригинальном блоке сайдбара

Заголовок H1

Пишем самый цепляющий результат (тот же принцип, что и написание Title). Также можно добавить что настроено, какие инструменты были использованы (смотрим по ключевикам для SEO, выбираем подходящие с наибольшей частотой)

Формула: {SEO ключевое слово по услуге} для {ниша}: {коротко результат и/ или инструменты}
